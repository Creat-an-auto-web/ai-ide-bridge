# 业务实现代码生成 Workflow

状态：已实现  
最后更新：`2026-10-02`

## 目标

第三阶段以第二阶段生成的测试代码为不可修改的规格，生成完整的业务/生产实现文件。
它不会修改工作区源码；结果先在 IDE 面板和阶段产物预览中展示，再由用户决定是否保留产物或应用最终任务补丁。

## 接口

```text
POST /v1/code-implementation/runs
```

输入包括需求规格、user story、测试计划、测试用例、固定测试文件和仓库根目录。后端从仓库根目录采集受限的源码快照，跳过凭据、环境文件、依赖目录和构建产物。

输出包括：

- `implementation_plan`
- `files`：完整业务实现文件内容
- `changed_files`
- `test_command`
- `quality_checks`

## 约束

- 生成文件路径必须位于仓库内。
- 固定测试文件不能出现在 `files` 中。
- `changed_files` 与生成文件路径必须完全一致。
- 生成文件必须是完整内容，不接受片段或省略号。
- 隔离测试会同时覆盖测试基线和生成的业务实现覆盖层。

## IDE 展示

Void 面板在测试代码草案之后显示“阶段三：业务实现代码生成”。生成后会展示实现计划、变更文件、测试命令、质量检查和每个文件的完整内容。阶段产物中，第二阶段测试基线位于 `02-test-cases/test-code/`，业务实现位于 `03-implementation/`。
